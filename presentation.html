04 • Payment Engineering

Razorpay Payments & Auto-Reconciliation

FinTech Security

Cryptographic Webhook Handshake

Orders transition from pending_payment to paid only when Razorpay’s cryptographic signature passes HMAC-SHA256 validation.

const expected = createHmac("sha256", secret);
const isValid = timingSafeEqual(expected, signature);
// Immune to timing side-channel attacks

Eliminates fraudulent client-side payment confirmation by verifying server-to-server.

Unpaid Stock Auto-Recovery Cron

When shoppers abandon payment, reserved product inventory is automatically returned to the store after 24 hours.

Inventory Lock 24-hour hold window
Daily Trigger Vercel Cron (`api/cron/daily`)

Reconciles any missed webhook events directly against Razorpay's API to ensure 0 lost payments.

Supported Payment Modes: UPI (GPay, PhonePe, Paytm), Debit/Credit Cards, NetBanking Currency: INR (Paise precision in DB)

09 • Data & Security

Database Schema & Security Model

Enterprise PostgreSQL

🗄️ Normalized PostgreSQL Schema

products price_minor, stock, slug
orders status, total_minor, addr
order_items product_id, qty, unit_price
payments razorpay_id, signature, ok
coupons code, discount_pct, active
phone_models brand, model, slug

Foreign key cascades and indexed queries ensure instant search and relational integrity.

🛡️ Multi-Layer Security Architecture

  • ✓ Row Level Security (RLS): Unauthenticated users can only view active products. Order records require secret token or admin session.
  • ✓ Server-Only Guards: Supabase service role keys are wrapped in server-only, never bundled into client JS.
  • ✓ Race Condition Prevention: Stock decrements occur via PostgreSQL stored procedures, preventing overselling during flash sales.
Database Host: Supabase Cloud (AWS Mumbai Region) Strict CSRF & XSS Protection
